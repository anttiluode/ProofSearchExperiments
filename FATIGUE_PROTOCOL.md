# Coupled Horn search: fatigue versus fairness (pilot)

Parent: [ProofSearchExperiment](https://github.com/anttiluode/ProofSearchExperiment). Harvests pre-selection recoverable fatigue from [CombinatoryPlaySol](https://github.com/anttiluode/CombinatoryPlaySol) and contextual feedback from [AliveAI](https://github.com/anttiluode/AliveAI).

This isolates scheduling, not general Lean proof search. Four competing Horn clauses each require a cycle of 3, 4 or 5 binary premises over 12 witnesses. Facts are indexed as outgoing/incoming bitsets. All assignments share variable identities, and only exact facts close a proof. Three independently generated families: sparse random edges, dense random edges, parity constraints with a conflicting or consistent final relation. For each family, 40 seeds, each with a paired negative built by enforcing inconsistent parity or incompatible adjacent endpoint supports in every clause; positive-labelled random instances are classified by an independent oracle (not assumed satisfiable). Rule order randomized; no selection based on regulator performance. All seeds frozen now (11000–11039). No hidden answer enters scheduling. Use unique assignment prefixes; no repeated exact state. This is a finite cyclic join/backtracking engine, not the parent's bidirectional router; that integration remains future work.

Every lane is a candidate clause and fixed first witness x. A live step extends one partial binding with the next indexed candidate or detects an empty/exhausted branch. At the final variable intersect the two incident constraints exactly (one bitset AND) for all arms. DFS state preserved across turns; no discarded frontier on reheating. Pre-selection score prefers deeper pending bindings; stable lane order. C/D subtract fatigue before selecting. A static score, B1 rule-family round-robin (lanes cyclic within family), B2 random active lane, C global rule fatigue, D contextual fatigue keyed by (rule, first bound witness), F discounted failure/success score (same contextual key), plus J direct exact ordered join DFS with exact last-variable intersection. All use the identical lane expansion and exact checks. Energy starts at 1, lazy recovery r=.015 per live step, burn b=.25 on observed conflict only, penalty 3*(1-E). Conflict means a zero next-candidate mask or an empty final intersection; ordinary stack exhaustion isn't a conflict. No burn merely for opening unresolved premises. F uses discounted failure EMA (recovery .015, update .25) as deliberately equivalent linear control before clipping; report equivalence where present, no novelty claim. A context key is a bound witness identity, not a learned semantic embedding. No persistent memory across problems.

Report at 256 and 1024 live steps; also report total index insertions, lane construction, scheduler candidate inspections, index probes, bitset ANDs, stack operations, regulator updates, certificate checks separately (not equivalent CPU timings). Report success, false positives, work all problems, paired per-seed outcome and win/loss on common solved cases; negatives only count as proved impossible on full exhaustion or independent oracle, never on timeout. A fair scheduler must eventually visit any surviving lane without a cap. Strong direct indexed join is the practical control; no claim that biological analogy beats exact methods without total-cost evidence. Fixed synthetic cases; no parameter tuning. Generate Lean theorems with used facts and supplied Horn rule; independent oracle and membership check required for every certificate. Kernel verification separately via CI.

Only proceed to macro-growth/SIM if warranted. No genuine LLM proposer loop in this pilot.
